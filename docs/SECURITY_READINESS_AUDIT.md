# مراجعة جاهزية قاعدة البيانات والأمان — الحازم سمارت

- تاريخ المراجعة: 2026-11-05
- المستودع: `hazemproooo5-boop/al-alamia-group--Alhazem`
- الفرع الذي تمت مراجعته: `fix/vite-runtime-bootstrap-2026-11-05`
- النطاق: جرد ساكن للملفات ومسارات التشغيل؛ لم يتم الاتصال بمشروع Supabase حي أو تنفيذ SQL.

## النتيجة التنفيذية

**لا يوجد دليل في هذا الفرع على تكامل قاعدة بيانات قابل للتشغيل أو نظام مصادقة/إدارة محمي.** توجد اعتماديات Supabase ومتغيرات بيئة نموذجية وملف Middleware خاص بـ Next.js، لكن نقطة دخول التطبيق الفعلية تشغل Vite وReact Router. لا توجد ملفات migrations أو API handlers المشار إليها في README ضمن المسارات التي جرى التحقق منها.

## أدلة مباشرة

1. `index.html` يشغل `/src/main.tsx` مباشرة.
2. `src/main.tsx` يركب `BrowserRouter` ويشغل `src/App.tsx`.
3. `package.json` يحدد أوامر `vite` للتطوير والبناء والمعاينة، بينما يحتفظ باعتماديات `next` و`@supabase/ssr` و`@supabase/supabase-js`.
4. `middleware.ts` يستورد `NextRequest` و`NextResponse` من `next/server`. هذا الملف ليس وسيطًا في دورة تشغيل Vite الحالية؛ وجوده وحده لا يحمي مسارات React Router.
5. ملف `.env.example` يحتوي أسماء متغيرات Supabase فارغة، ولا يثبت وجود مشروع Supabase أو أسرار صالحة.
6. README يذكر `database/migrations/001_core.sql` وملفات migrations 002–004 و`database/seeds/001_reference.sql`. محاولة قراءة هذه المسارات على فرع المراجعة أعادت 404؛ لا يجوز تطبيق migrations غير موجودة أو افتراض أن الجداول والسياسات قد أُنشئت.
7. مسار `/admin` في `src/App.tsx` يعرض أرقام جودة مشتقة من بيانات seed محلية. لا يوجد في هذا المسار فحص جلسة أو دور مستخدم، ولا يظهر فيه اتصال API أو قاعدة بيانات. لذلك لا يصح وصفه بأنه لوحة إدارة محمية.
8. لم تظهر ملفات `src/app/api` أو `app/api` أو `pages/api` ضمن ملفات PR المعدلة؛ ولا تكفي وثائق README لإثبات وجود endpoints.

## ما لا ينبغي فعله الآن

- لا تضع مفاتيح خدمة Supabase أو `service_role` في الواجهة أو متغيرات `NEXT_PUBLIC_*`.
- لا تفعّل نماذج تجار أو عملاء أو إدارة على أساس الواجهة الحالية.
- لا تعتمد على `middleware.ts` لحماية Vite routes.
- لا تنشئ جداول أو سياسات RLS تخمينية، ولا تطبق migrations غير موجودة.
- لا تعتبر `/admin` آمنًا أو مصدرًا لبيانات تشغيلية.

## خطة الاستكمال الآمنة

1. اعتماد قرار معماري واضح: إما استعادة تطبيق Next.js الكامل بما فيه API routes، أو بناء backend موثق منفصل بجانب Vite. لا تخلط middleware خاصًا بـ Next.js مع تشغيل Vite وتفترض أنه يعمل.
2. استعادة/إنشاء migrations دائمة ومراجعة متسلسلة من مخطط قاعدة البيانات الحقيقي، مع مفاتيح خارجية وقيود وفهارس وسياسات RLS لكل جدول.
3. إنشاء عميل Supabase للمتصفح باستخدام المفتاح العام فقط، وعميل خادم منفصل لاستخدام الأسرار على الخادم فقط.
4. تنفيذ مصادقة خادمية والتحقق من الدور داخل كل API handler؛ إخفاء عناصر الواجهة ليس حماية.
5. اختبار RLS بحساب مجهول، وعميل عادي، وتاجر، وموظف مبيعات، ومدير؛ واختبار منع القراءة/التعديل المتبادل.
6. إضافة موافقات مستقلة وواضحة لمعالجة بيانات طلب التواصل والتسويق، مع تسجيل وقت الموافقة والغرض وإمكانية سحبها.
7. اختبار CRUD ورفع الملفات وحدود النوع والحجم وتسجيل Audit Log دون أسرار.
8. تشغيل migrations على مشروع Supabase تجريبي فقط، ثم اختبارات CI وTypeScript وBuild قبل أي نشر.
