## 1. ملخص تنفيذي
- المسارات المعرّفة فعلياً في `src/App.tsx`: الرئيسية، تقييم الاحتياج، البحث الذكي، تفاصيل المنتج، المقارنة، المستشار، العلامات التجارية، تفاصيل العلامة، مركز الكتالوج، التكييف، لوحة الإدارة، و404.
- الصفحة الرئيسية تعرض أقساماً أولية للعلامات والمنتجات والتكييف والعروض والأخبار والنصائح والمسابقات والأكاديمية، لكن بياناتها مستوردة من `src/data/seed.ts` وليست دليلاً على ربط قاعدة بيانات حية.
- البحث والمستشار والأسعار والتحقق تعمل وفق خدمات محلية تقرأ بيانات seed؛ لم يظهر في الملفات المفحوصة Repository أو Supabase client مستخدم لهذه الوظائف.
- يوجد تعارض تشغيل مؤكد: `package.json` يطلق Next.js، بينما `index.html` و`src/main.tsx` و`vite.config.ts` بنية Vite/React Router. وملف `src/App.tsx` يعتمد `react-router-dom` غير المعلن في dependencies المعروضة.
- لا تُعامل أوصاف README عن API وmigrations وصفحات إضافية كدليل تنفيذ؛ يلزم مطابقة كل مسار بملفه الفعلي قبل اعتماده.

## 4. مراجعة مصادر البيانات والثقة
### مثبت في الملفات
- `src/data/seed.ts` يحتوي 5 علامات و3 منتجات وأسعاراً ومحتوى أولياً.
- الأسعار والتواريخ المسجلة تعود إلى مايو 2026؛ يجب اعتبارها بيانات قديمة إلى أن يعاد التحقق من المصدر.
- توجد قيمة GTIN تجريبية/نمطية في منتج AUX (`1234567890123`)؛ لا يجوز عرضها كمعرّف منتج موثق.
- بعض الروابط في seed روابط عامة لمواقع العلامات وليست صفحة مصدر دقيقة لمواصفة أو سعر محدد.
- `searchService` و`advisorService` و`priceService` تعتمد على مصفوفات seed.
- `verificationService` يحسب مؤشرات على بيانات seed فقط، ولا يثبت تدقيق قاعدة بيانات فعلية.

### ضوابط قبل النشر
1. وضع علامة واضحة على أي بيانات تجريبية وعدم عرضها على أنها بيانات بيع حالية.
2. إعادة التحقق من كل سعر وتوفر وضمان ومواصفة مع مصدر محدد وتاريخ تحقق.
3. إزالة/تصحيح GTIN غير الحقيقي بعد التحقق من رقم المنتج الرسمي.
4. عدم استخدام وصف «سعر الحازم» إلا إذا كان السعر صادراً فعلياً عن الشركة.
5. حسم تناقض بيانات الاتصال بين README وseed وملفات البيئة قبل إظهارها للعميل.

## 5. عوائق البناء والربط
1. **Runtime متعارض:** Next.js في scripts/dependencies مقابل Vite/React Router في entry points وconfig.
2. **اعتماديات غير متطابقة:** `react-router-dom` وVite plugins مستخدمة/مشار إليها ولا تظهر في dependencies المعروضة؛ في المقابل لا يظهر App Router page في الملفات التي جرى فحصها.
3. **قاعدة البيانات:** لم يظهر في الخدمات التي جرى فحصها اتصال Supabase؛ لا يجوز الادعاء بأن Search/Advisor/Compare تستخدم قاعدة حقيقية.
4. **اختبارات التشغيل:** لا تتوفر نتيجة فعلية لـ install/typecheck/lint/tests/build في هذه الجولة.
5. **وثائق التنفيذ:** بعض الملفات والمسارات وmigrations التي يسردها README لم يتم إثبات وجودها في الجرد السابق؛ يجب التحقق من كل مسار مباشرة قبل البناء عليه.

## 6. ترتيب التنفيذ المقترح — دون حذف أو استبدال
1. تثبيت قرار Runtime النهائي على Next.js وفق NOVA، بعد جرد كل الملفات والصفحات الحالية؛ نقل وظائف React Router الحالية مع الحفاظ عليها، لا إسقاطها.
2. إعداد بيئة قابلة للتشغيل على فرع العمل، ثم تثبيت الاعتماديات وإنشاء lockfile بعد نجاح التثبيت.
3. إنشاء/استعادة طبقة البيانات الفعلية وSupabase migrations والسياسات من الملفات الموجودة والمرجعيات؛ لا اختراع مخطط بديل إذا كانت migrations الأصلية متاحة.

6. استكمال المصادقة وصلاحيات الخادم وRLS وسجل التدقيق قبل إتاحة لوحة الإدارة أو بيانات العملاء.
7. إضافة اختبارات تغطي كل Route وتدفق، ثم تنفيذ build/typecheck/lint والاختبارات وتوثيق النتائج الفعلية.
